# Code Compare 비교 옵션 점검

기준일: 2026-11-10 (Asia/Seoul). 아래 진단은 수정 전 이력이다. 사용자 후속 요청으로 로컬 기능을 수정하고 검증했으며 최신 수정 결과는 하단을 따른다. 실제 Pages에는 아직 이 변경을 게시하지 않았다.

## 수정 전 결론

분석 엔진의 통계·목록에는 옵션이 적용되지만, Monaco 에디터 강조와 같은 규칙을 사용하지 않아 결과가 모순되는 경우가 재현됐다. 특히 줄 끝 공백 무시를 켰을 때 들여쓰기 차이까지 에디터에서 숨겨지는 문제가 있다. 문서에 일부 제약이 안내돼 있었더라도 사용자가 비교 결과를 오해할 수 있는 UI 동작이다.

## 검사 범위

- 로컬 fc3c173 production build, Windows의 실제 Microsoft Edge.
- 합성 입력13종 × Side-by-Side/Unified =26개 시나리오. 각 시나리오에서 옵션 OFF → ON → OFF, 추가/삭제/블록 통계·탐색 버튼·Monaco 강조, Original/Modified 원문 다운로드를 확인했다.
- 포함 입력: 행 내부/앞/뒤 공백, 빈 줄과 파일 끝 빈 줄, 대소문자, CRLF/LF/CR, 실제 내용 변경,5개 옵션 조합, 마지막 개행 유무.
- 분석의 기대 연산 수와 옵션 복원은26개 모두 일치했다. 양쪽 원문 다운로드도 모두 정확히 보존됐다. pageerror·외부 요청0.
- 분석 결과와 화면 강조의 변경 유무가 한 단계 이상 달라진 것은26개 중16개다. 에디터 decoration 개수는 변경 줄 수와 같지 않으므로 일치 여부 판정에는 강조 유무만 사용했다.
- 이 관찰 검사의 실행 성공은 제품 기능 전체 정상 판정을 뜻하지 않는다. 검사 중 확인한 불일치는 아래 미해결 항목이다.

## 옵션별 결과

| 옵션 | 분석 통계·목록 | 에디터에서 재현한 문제 |
| --- | --- | --- |
| 공백 무시 | 내부 공백/들여쓰기 차이를0으로 처리 | `const x = 1;`와 `const x=1;`는 켜도 내부 공백 강조가 남는다. 들여쓰기만 다른 경우에는 강조도 사라진다. |
| 줄 끝 공백 무시 | 후행 공백은0, 들여쓰기 차이는+1/−1 유지 | `  value`와 `value`는 통계·목록에 변경이 남는데 강조는 사라진다. 후행 공백만 다른 경우는 정상적으로 둘 다 사라진다. |
| 빈 줄 무시 | 중간/끝의 추가 빈 줄은0 | 빈 줄 삭제 표시가 에디터에 남는다. |
| 대소문자 무시 | `Name`/`name`, `Hello`/`hello`는0 | 대소문자 강조가 에디터에 남는다. 실제로 다른 `Hello`/`Bye`는 계속 변경으로 판정한다. |
| 줄바꿈 형식 무시 | 켜면 CRLF/LF/CR 차이0, 끄면 변경으로 복원 | 꺼도 EOL 자체의 차이를 에디터는 강조하지 않는다. 두 줄 예제에서 분석은+2/−2지만 강조는0이다. |

- 같은 문제가 Side-by-Side와 Unified에서 재현됐다.
-5개 옵션 조합도 분석0/에디터 강조 유지가 재현됐다.
- `a\n`과 `a`의 마지막 개행 차이는 줄바꿈 형식 무시를 켜도 변경으로 유지된다. CRLF/LF/CR 형식 무시와 마지막 개행 유무는 별개라는 현재 정책이며 이번 검사에서 새 오류로 판정하지 않았다.

## 원인과 기존 테스트의 빈틈

- core/diff.ts의 Text 엔진은 옵션별 정규화·빈 줄 필터를 사용한다.
- CodeCompare.tsx는 Monaco에 ignoreWhitespace 또는 ignoreTrailingWhitespace가 켜지면 동일한 ignoreTrimWhitespace=true를 전달한다. 설치된 Monaco의 이 옵션은 줄 앞/뒤 공백을 함께 무시하므로 줄 끝 공백 전용 옵션과 의미가 다르다. 행 내부 공백·빈 줄·대소문자용 동일 규칙은 전달하지 않는다.
- EOL은 Monaco의 줄 단위 시각 비교와 원문 문자열 기반 분석에서 처리 방식이 다르다.
- 기존351개 단위·통합 테스트 및 기존 옵션 E2E는 분석 결과·원문 보존을 확인하지만, 모든 옵션의 분석/에디터 강조 일치까지 확인하지 않아 위 문제를 잡지 못했다.
- README의 “Monaco 공백 무시는 줄끝 공백 기준” 설명도 정확하지 않아 “줄 앞/뒤 공백”으로 정정했다. 동작 수정이나 설계 방식 확정은 이번 점검에 포함하지 않았다.

## 검증과 후속

npm test351/351, typecheck/lint/production build 통과. 기존 Monaco chunk·Tree-sitter 경고 유지. 진단용 스크립트·원시 JSON·캡처는 ignored test-results/option-audit/에 저장했으며 제품 코드에는 추가하지 않았다.

우선 수정 대상은 분석과 시각 강조의 비교 규칙 불일치, 특히 후행 공백 옵션이 들여쓰기를 숨기는 현상이다. 이후에는 원문/물리 줄 번호/편집/다운로드를 보존하면서 옵션별 에디터 강조·통계·목록·탐색·접기 결과의 회귀 검증을 추가해야 한다. 이번 점검 결과를 수정 완료나 Phase9 완료로 표시하지 않는다.

## 실제 배포본 재확인

https://heoseongbin.github.io/CodeDiff-Studio/ 에서 공백 무시(행 내부), 줄 끝 공백 무시(들여쓰기), 빈 줄 무시, 대소문자 무시, EOL 무시5개 사례를 Side-by-Side로 재검사했다.5개 모두 로컬과 같은 불일치를 재현했다. 옵션 OFF/ON/OFF 통계와 원문 다운로드는 기대와 일치했고 pageerror/외부 요청0이었다.

처음 배포 진단 실행은 검사 스크립트가 프로젝트 하위 경로 대신 도메인 루트로 이동해 Monaco를 찾지 못했다. 진단 주소를 ./로 바로잡고 위5개를 재실행해 확인했다. 이 자동화 주소 오류는 제품 결함으로 집계하지 않았다.

## 후속 수정 · 로컬 구현

- Code Compare의 통계·목록과 에디터가 동일한 Text 엔진 hunks를 사용하도록 수정했다. 별도 줄 비교/정규화된 편집 문서는 만들지 않는다. 변경이 무시되면 강조도 지우고, 줄 끝 공백 옵션은 들여쓰기 변경을 숨기지 않는다.
- Worker의 Code Compare 요청에만 시각 범위를 투영한다. 무시된 문자/빈 줄은 모델과 원문에 유지하고 원래 물리 줄·UTF16 열로 돌아간다. EOL/EOF는 행 강조와 injected 줄 끝 표기로 확인하며 라벨을 모델 값이나 다운로드에 넣지 않는다.
- 범위가 큰 변경은 줄 내부 비교 예산을 제한하고 행 강조로 폴백한다. 선택 상세와 Patch는 계속 원문 기준이다.
- Monaco0.52.2 인스턴스별 child service 어댑터를 사용하며 버전 업데이트에는 재검증이 필요하다(ADR-024). Folder/Syntax의 native provider와 JSON 처리 정책은 변경하지 않았다.
- src/tests/visual-diff.test.ts23개 추가 후 단위·통합374개 통과. e2e/compare-options.spec.ts는13종 × 좌우/Unified26개 외에 물리 줄·접기/편집·빈 입력/EOF·100개 빈 줄 이후 탐색16개를 포함한다. 최종 전체 회귀 결과는 PROGRESS에 기록한다.
- 최초 전역 초기화 후 무시되는 createDiffEditor override 접근은 브라우저 검사에서 실패해 폐기했고, Code Compare 인스턴스만 격리하는 방식으로 재검증했다. EOL zero-length 라벨도 표시가 필요하도록 수정했다. 초기 진단 결과와 수정 후 검증을 혼동하지 않는다.

현재 수정은 로컬 작업 트리에만 있으며 미커밋·미푸시·미배포다. 위 실제 사이트 재현은 수정 전 배포본에 대한 기록이며 실제 사이트가 고쳐졌다고 주장하지 않는다.
