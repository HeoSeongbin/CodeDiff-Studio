# JSON ↔ CSV 변환 동작 점검

2026-11-10 (Asia/Seoul). 아래 점검은 수정 전 이력이다. 사용자 후속 요청으로 CSV 기능을 로컬에서 수정했으며 최신 결과는 하단을 따른다. 이전 Code Compare 수정 작업 트리는 보존했다. 실제 사이트에는 아직 이 수정본을 게시하지 않았다.

## 수정 전 확인 결과

정상 객체 배열의 JSON → CSV와 CSV → JSON은 작동한다. 그러나 Flatten의 음수 처리와 빈 데이터의 완료 표시는 문제가 있다. 기본 JSON 예제가 CSV 입력 계약과 다른 점, 엄격한 CSV 빈 행/헤더 정책도 사용 혼동을 일으킬 수 있다.

### 1. Flatten을 켜면 숫자 음수가 문자열로 바뀜 — 수정 필요

```json
[{"amount":-12,"nested":{"value":-3}}]
```

Flatten OFF에서는 amount가 -12로 출력된다. ON에서는 다음처럼 수식 방어 접두사가 붙는다.

```csv
/amount,/nested/value
"'-12","'-3"
```

이 CSV를 타입 추론으로 다시 읽어도 숫자 -12가 아니라 작은따옴표를 포함한 문자열 "'-12"가 된다. 로컬 core·Worker/UI·다운로드 및 실제 배포 사이트에서 재현했다.

원인은 core/json/csv.ts의 flatten이 숫자/boolean/null leaf도 문자열로 만드는 데 있다. 뒤의 Papa.unparse(escapeFormulae=true)는 문자열의 '-' 시작을 수식 후보로 보아 접두사를 추가한다. 문자열 수식 방어 자체는 유지해야 하지만 숫자 타입까지 문자열로 먼저 바꾸는 것은 별도 문제다. 이 요청에서는 수정하지 않았다.

### 2. [] / [{}]은 버튼을 눌러도 결과나 오류가 안 보임 — 표시 개선 필요

코어 변환 결과가 빈 문자열이고 UI의 `{output && ...}` 조건에 걸려 미리보기·저장 버튼이 나타나지 않는다. 데이터/컬럼 없음 또는 변환할 수 없음 안내도 없어 무반응처럼 보인다. []는 로컬/실배포, [{}]은 로컬에서 확인했다. 빈 데이터가 의미 있는 Header/테이블을 만들지 못한다는 점과 별개로 완료/입력 안내가 필요하다.

### 3. 기본 JSON 예제는 그대로 CSV로 변환할 수 없음 — 입력 계약/UX

JSON Tools 기본 예제는 단일 객체지만 JSON → CSV는 **객체 배열**만 지원한다. 처음 CSV 탭에서 바로 실행하면 "JSON → CSV는 객체 배열을 입력하세요."라는 오류가 나온다. 로컬/실배포 모두 재현했다. PROJECT의 Object Array 요구사항과 일치하는 현재 계약이며, 기본 예제/안내를 변환 작업에 맞춰 개선하면 혼동을 줄일 수 있다.

정상 입력 예시:

```json
[{"name":"홍길동","age":30},{"name":"Heo","age":28}]
```

### 4. 빈 Header의 내보내기/가져오기 정책 불일치

`[{"":1}]`은 빈 이름의 Header를 가진 CSV로 내보내지만, fromCsv는 같은 결과를 "CSV Header가 비어 있거나 중복되었습니다."로 거부한다. 단위 진단과 로컬 UI 내보내기에서 확인했다. 빈 키를 지원하지 않을 거라면 내보내기에서도 명시적 검증/안내가 필요하다.

## 정상 동작과 현재 제약

- 한글, 셀 안의 쉼표·따옴표·줄바꿈을 포함한 객체 배열/CSV가 정상 변환됐고 다운로드가 미리보기 원문과 일치했다.
- 컬럼 선택과 선택 순서가 적용된다. 전체 해제 시 모든 컬럼을 쓰는 것은 현재 화면에 안내된 정책이다. 체크 후 이름에 (#1) 같은 순번이 붙는다.
- CSV → JSON에서 comma/semicolon/tab을 맞춰 선택하면 정상 파싱된다. 타입 추론 OFF는 숫자도 문자열, ON은 안전한 숫자/boolean/null로 변환한다. 001과9007199254740993은 문자열로 보존됐다.
- 중복 Header·컬럼 수 불일치·닫히지 않은 따옴표는 오류로 표시되고 결과는 표시되지 않았다.
- 다중 컬럼 CSV 중간의 완전히 빈 행은 현재 컬럼 수 불일치로 거부한다. skipEmptyLines=false/엄격한 행 길이 정책 때문이며, 일반적인 빈 행 포함 파일을 쓰려면 정책/옵션 개선 또는 빈 행 제거가 필요하다.
- CSV → JSON은 오른쪽 CSV 입력을 사용한다. 왼쪽 JSON 원문이 문법 오류여도 CSV 변환 자체는 성공하지만 왼쪽 JSON 오류는 남는다. 변환 방향과 입력창 분리가 사용 혼동을 줄 수 있다.
- 중첩 Flatten의 Header는 JSON Pointer이며 CSV → JSON이 자동으로 원래 중첩 구조를 복원하지는 않는다. 수식 시작 문자열의 접두사는 의도된 안전 정책이다. 이를 음수 숫자의 Flatten 문제와 구분한다.

- UI에는 기본 객체/정상 배열/컬럼 선택·해제/음수 Flatten OFF·ON/빈 배열·객체/빈 Header/CSV 양방향·구분자·타입 추론/오류·새 입력 시 결과 폐기를 포함했다. 진단 JSON과 화면은 ignored test-results/csv-audit/에 저장했다.
- 모든 표시된 결과의 다운로드가 미리보기 textContent와 일치했다. pageerror·외부 요청0. 실제 파일의 내용을 서버로 업로드하지 않고 합성 입력만 사용했다.
- 초기 진단은 결과가 렌더되기 전 읽는 문제와 선택 후 바뀌는 체크박스 이름을 누락해 실패했다. 렌더 완료/원문 textContent와 선택 순번을 반영해 전체를 재실행했다. 이 진단 선택자 오류는 제품 결함으로 집계하지 않았다.
- npm test374/374, typecheck/lint/production build 통과. 기존 테스트 통과는 위 발견 사항이 정상이라는 뜻이 아니다. 현행 테스트가 음수 Flatten과 빈 결과 UI 안내를 충분히 검증하지 않았다.
- CSV 코어·JSON 도구 UI/상태는 수정하지 않았다. 기존 Code Compare 변경과 문서는 보존했다. 커밋·푸시·배포도 하지 않았다.

## 후속 수정 · 로컬 구현 및 검증

1. Flatten에서 숫자/boolean/null 타입을 보존한다. 숫자 -12/-3은 그대로 내보내고 수식 시작 문자열에는 기존 접두사를 유지한다. 배열/객체 셀의 JSON 문자열 정책과 JSON Pointer Header는 유지한다.
2. []/[{}] 또는 실제 선택 컬럼 없음·빈/공백 Header는 명시적 오류를 표시한다. 오류는 CSV 변환 버튼 옆에 있어 모바일에서 무반응처럼 보이지 않는다.
3. JSON→CSV의 예제 버튼은 객체 배열을 제공한다. 탭을 열었다는 이유로 원문을 자동 교체하지 않는다. CSV→JSON은 왼쪽 Source CSV를 사용하며 관련 없는 JSON 오류는 숨기고 기존 JSON 입력/모델은 보존한다.
4. 빈 행 건너뛰기는 기본 OFF인 선택 옵션이다. 켜도 인용된 빈 값·공백/구분자 데이터·인용 내부 줄바꿈은 버리지 않는다. 오류 번호는 원래 CSV 레코드 순서다.
5. 입력/옵션 변경은 이전 결과를 지우고 진행 중인 Worker를 취소한다. CSV 파일을 읽은 직후에는 디코딩한 CRLF 원문을 저장하며 textarea에 입력/편집할 때는 LF 정규화가 가능하다.

신규 csv-regressions.test.ts23개를 포함한 단위·통합397/397, typecheck/lint/build 통과. 신규 CSV E2E는 음수·빈 입력·Header·3구분자·타입 추론·예제·원문/모델 보존·새 입력 취소·다운로드·모바일을 포함한다. 최종 전체 E2E 수치는 PROGRESS를 따른다. CSV23개 단위 테스트의 최초3개 fixture 인자 오류와 E2E의 편집 LF 기대값은 고친 뒤 재검증했다. 실제 제품의 데이터 손실을 테스트 기대값 수정으로 숨기지 않으며 파일 업로드 CRLF는 별도로 정확히 검사한다.

이전 Code Compare 미커밋 수정은 유지했다. 현재 수정은 미커밋·미푸시·미배포이며 위 실제 사이트 재현은 수정 전 버전의 이력이다.

CSV 후속 최종 검증: 단위·통합397/397, production Edge93/93 및 typecheck/lint/build 통과. 신규 CSV23개 단위·Worker 통합과17개 UI 회귀를 포함한다. csv-conversion-fixed/mobile.png는 로컬 수정 화면이고 실제 사이트는 아직 미배포다.
